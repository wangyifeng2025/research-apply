## 进度（2026-10-22）

教师填报从阶段 3、阶段 4 提前完成，可以在页面上从新建走到提交。审核、附件和管理端增删改没有提前。

已经可用：

- 教师登录后在 `/applications` 看到本人申报，按状态筛选，并新建社会科学类、自然科学类或双高专项草稿。双高专项使用自科申报书，类别单独记录。
- 保存草稿、上一步、下一步、返回列表都会保存当前栏目。点顶部「工作台」不保存。参加者、成果、进度、设备在保存栏目时整组替换。
- 提交做字段校验，错误显示在页面上。已提交且尚未系部审核的申报可以撤回。只有草稿可以删除。
- 自科主要研究内容是一个文本框，说明为：主要填写目标与任务需求分析，主要技术难点和问题分析，研究与开发任务与内容，关键技术、技术难点、创新点等。
- 自科主要技术经济指标按申报书排成两段：（一）量化考核指标，含科技产出和研发服务能力；（二）主要技术经济指标及社会效益说明。论文按核心期刊、一般期刊分别填国际、国内、省级，省级核心期刊不能填。数字用下划线输入；空值显示占位 0，输入时不会变成 01。
- 经费科目接口 `GET /api/budget-subjects?family=` 已提供，预算按万元填写并在页面上汇总。

尚未做到、仍留在原任务里：

- 每人每批次只能负责 1 项还没有限制。
- 没有独立的 `services/workflow.rs`，也没有接口测试。
- 校验规则写在申报服务里，前端只对基本情况做了同样的检查，没有按需求 6.3 逐条建立 zod schema。
- 长文本没有实时字数。提交失败的错误列在页顶，还不能点一下跳到对应章节。
- 登录页和按角色区分的工作台已经有了，未登录仍可打开页面地址；管理页还不能维护部门、用户和批次。

## 二、计划原则

1. **按业务链路纵向推进**：每个阶段交付一条可演示的链路（登录 → 教师填报 → 审核 → 盲审），而不是先写完所有后端再写前端。
2. **先后端、后页面**：每条链路先完成接口和服务层测试，再接页面，减少返工。
3. **规则只写一份**：服务层校验规则集中在 `services/validation`，与需求 6.3 逐条对应；前端 zod schema 按同一清单编写，联调时逐条对照。
4. **待确认事项设截止时间**：需求第十一节的问题在对应阶段开始前必须有结论，否则按本文档的默认方案实施（见第四节）。
5. **初始迁移冻结**：从阶段 1 开始，任何表结构变更都新增迁移文件。

## 七、质量要求

### 完成标准（每个任务）

- 后端：接口有成功、校验失败、越权三类测试；`cargo fmt`、`clippy`（无警告）、`test` 通过；
- 前端：`npm run lint`、`npm run build` 通过；表单在后端返回字段错误时能正确显示；
- 涉及需求变更时同步修改 `docs/requirements.md`；
- 涉及表结构变更时新增迁移、重新生成实体、更新需求第六节。

## 八、风险与应对

| 风险                               | 影响                   | 应对                                                             |
| ---------------------------------- | ---------------------- | ---------------------------------------------------------------- |
| 待确认事项迟迟没有结论             | 审核流返工             | 按第四节默认方案实施，结论变化时只调整服务层规则，表结构已预留   |
| 自然科学指标已按申报书表格接上保存；只读排版（T4-11）仍未做 | 审核人看到的版式和填报不一致 | 只读页按纸质申报书顺序排，指标表复用同一套格子                   |
| 服务层规则与前端 zod 不一致        | 用户看到前后矛盾的提示 | 两边都以需求 6.3 为唯一来源；联调时逐条走查                      |
| 盲审信息泄露                       | 合规问题               | 专家接口使用独立 DTO；增加"序列化结果不含身份字段"的自动化测试   |
| 重新生成实体覆盖手写代码           | `before_save` 等丢失   | 手写逻辑放在 `entity` 之外，或生成后用脚本检查                   |
| 申报开放时间早于计划               | 上线压力               | 阶段 7 的通知、审计查询可延后；最低可上线范围为 M3 + 附件 + 部署 |
